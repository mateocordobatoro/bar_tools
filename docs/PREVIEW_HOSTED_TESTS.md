## Procedure and credentials

`scripts/test-supabase-preview.mjs` is a separate hosted procedure. It hardcodes
Preview's HTTPS origin, session pooler host, port 5432 and project-specific login;
checks branch, configured public URL, official CA fingerprint and TLS hostname;
and verifies the empty Auth/application state and seven RLS tables before writes.
Auth settings must show signup disabled and email enabled. The existing admin key
must successfully list users on this exact Preview origin before provisioning.
No admin key is used for PostgREST: application requests use the publishable key
and real user JWTs, including a deliberately tampered JWT rejection test.

Run the prepared private macOS launcher:

```sh

```

In Preview Dashboard → Settings → API Keys, obtain the **existing secret key**
(`sb_secret_...`) privately. Enter it only in the launcher's hidden key prompt,
then enter the database password in its second hidden prompt. Do not paste either
in chat, command arguments, files or shell history. Do not create/rotate a key.
If no existing secret key is available, stop for review. Terminal must be a TTY;
getpass falls closed if hidden input cannot be used.

The launcher sends credentials through an anonymous stdin pipe to Node, never
command arguments or environment variables. Generated random test passwords and
sessions stay only in process memory. The report and inventory omit passwords,
keys, JWTs, refresh tokens and raw upstream errors/bodies. Auth creation uses the
server-only [admin API](https://supabase.com/docs/reference/javascript/auth-admin-createuser)
with email confirmation, not signup, invitations or email delivery.

Local prerequisites: Node 24, existing pg 8.16.3 in the isolated runtime
`/tmp/bar-tools-db-test-runtime`, and the verified CA in
`~/.postgresql/bar_tools_preview-ca.crt`. No dependency installation or live schema
change is performed by the launcher. The SQL connection uses explicit settings;
it does not rely on startup PGOPTIONS that the pooler previously ignored.
